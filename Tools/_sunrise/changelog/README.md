# Чейнджлог Sunrise

Чейнджлог добавляется в описание PR. Проще всего скопировать пример ниже и заменить текст и ссылки своими. Пояснения внутри `<!-- таких стрелочек -->` — это HTML-комментарии: они помогают заполнить блок, но не попадают в чейнджлог и могут быть оставлены на месте.

## Полный пример

```md
<!--
Заголовок начинает чейнджлог.
После :cl: укажите имя, под которым запись появится в Discord.
Если оставить имя пустым, будет использовано имя автора PR.
-->
:cl: Капитан Пупкин
<!--
add — новая возможность, предмет, механика или другой заметный контент.
Пишите результат для игрока, а не технические подробности реализации.
Строки без нового типа продолжают предыдущую запись.
Переносы сохранятся в Discord. Отступы перед продолжением необязательны.
-->
- add: Добавлена переносная кофемашина, которую можно заказать в грузовом отделе.
  Машина принимает стаканы, молоко и сиропы.
  При осмотре показывается оставшееся количество воды.
<!--
Каждая строка media относится к ближайшей предыдущей записи.
Порядок смешанных изображений, видео и внешних ссылок сохраняется.
Подпись внутри квадратных скобок будет показана вместе с медиа.
-->
media: ![Общий вид кофемашины](https://example.org/changelog/coffee-machine.png)
media: [Короткая демонстрация приготовления кофе](https://example.org/changelog/coffee-demo.webm)
media: ![Меню выбора напитка](https://example.org/changelog/coffee-menu.jpg)
<!--
Страница YouTube не является прямым видеофайлом.
Она появится подписанной кликабельной ссылкой на этом же месте.
-->
media: [Полный обзор на YouTube](https://www.youtube.com/watch?v=dQw4w9WgXcQ)

<!--
fix — исправление ошибки. Один пустой отступ между записями разрешён.
Не пишите «исправлены баги»: объясните, что именно снова работает.
-->
- fix: Исправлено исчезновение предметов при закрытии рюкзака во время движения.
  Предметы, уже лежавшие в рюкзаке, также больше не теряются.
<!-- GIF можно передать как прямое изображение. -->
media: ![Исправленное закрытие рюкзака](https://example.org/changelog/backpack-fix.gif)
<!-- Обычная ссылка без подписи тоже поддерживается. -->
media: https://example.org/changelog/backpack-before.png
media: https://example.org/changelog/backpack-after.png

<!-- tweak — изменение или перебалансировка уже существующего поведения. -->
- tweak: Уменьшено время приготовления эспрессо с десяти до пяти секунд.
  Шум кофемашины теперь слышен только в соседних помещениях.
<!--
Ссылка на Vimeo, как и ссылка на YouTube, будет кликабельной строкой.
Прямое изображение после неё останется после неё — тип медиа порядок не меняет.
-->
media: [Сравнение скорости на Vimeo](https://vimeo.com/76979871)
media: ![Новая таблица напитков](https://example.org/changelog/coffee-recipes.webp)

<!-- remove — удаление контента или возможности. -->
- remove: Удалены устаревшие одноразовые кофейные картриджи.
  Существующие картриджи на картах заменены многоразовыми контейнерами.
media: ![Новый контейнер вместо картриджа](https://example.org/changelog/reusable-container.png)
media: [Замена предмета на карте](https://example.org/changelog/container-replacement.mp4)

<!--
Явная граница завершает чейнджлог.
Всё ниже неё — Summary by CodeRabbit, примечания ревью и любой другой текст PR — игнорируется.
-->
:end-cl:

<!-- Этот текст находится за границей и частью чейнджлога не станет. -->
## Summary by CodeRabbit
Автоматическое резюме изменений.
```

Ссылки `example.org` в примере — заглушки: перед отправкой замените их прямыми HTTPS-ссылками на свои файлы. Ссылка должна открывать само изображение или видео, а не страницу сайта с ним. Страницы YouTube, Vimeo и подобных сервисов разрешены, но выводятся как подписанные ссылки, поскольку Discord не умеет надёжно строить из них элементы галереи.

## Медиа в чейнджлоге

Медиа позволяет приложить к конкретному изменению изображения, GIF-анимации, видео или ссылки на внешние сервисы. Каждая строка `media:` относится к ближайшей предыдущей строке `add`, `fix`, `tweak` или `remove`. В Discord текст изменения показывается перед его медиа, а медиа следующего изменения отделяется видимым разделителем.

> [!NOTE]
> Медиа используется только при публикации в Discord. Игровой клиент читает текст чейнджлога как раньше и пропускает дополнительное поле `media`.

### Основной синтаксис

Поддерживаются три равнозначные формы записи:

```md
:cl: Имя автора
- add: Добавлена новая кофемашина.

<!--
Восклицательный знак оставляет строку похожей на обычное изображение Markdown.
Тип файла всё равно определяется по содержимому, а не по знаку ! или расширению URL.
Текст в квадратных скобках станет подписью медиа.
-->
media: ![Общий вид кофемашины](https://example.org/changelog/coffee-machine.png)

<!--
Та же форма без ! обычно удобнее для видео.
Это только оформление исходного текста: парсер обрабатывает обе формы одинаково.
-->
media: [Демонстрация приготовления кофе](https://example.org/changelog/coffee-demo.webm)

<!--
Можно указать только URL. Файл будет опубликован без пользовательской подписи.
-->
media: https://example.org/changelog/coffee-menu.jpg
:end-cl:
```

`!` перед квадратными скобками не заставляет систему считать ссылку изображением. Загрузчик проверяет сигнатуру — фактическое содержимое файла — и самостоятельно выбирает подходящее расширение для Discord. Поэтому постоянная ссылка GitHub вида `https://github.com/user-attachments/assets/UUID` работает без `.png` или `.mp4` в конце.

> [!IMPORTANT]
> Используйте исходную постоянную ссылку `github.com/user-attachments/assets/...`. Не копируйте конечный адрес `github-production-user-asset...` с параметрами `X-Amz-*`: это временная ссылка, которая перестанет работать через несколько минут.

### Как загрузить файл через GitHub

1. Откройте редактирование описания PR.
2. Перетащите изображение или видео в поле описания либо вставьте его из буфера обмена.
3. Дождитесь завершения загрузки. GitHub вставит Markdown или отдельный URL.
4. Скопируйте адрес `https://github.com/user-attachments/assets/...` в строку `media:`.
5. Сохраните описание PR и проверьте ссылку в приватном окне браузера. Если она открывается без авторизации, публикация сможет скачать файл.

```md
:cl: Имя автора
- fix: Исправлено зависание интерфейса после закрытия окна.
<!--
У GitHub-вложения нет расширения в URL — это нормально.
Подпись «Короткая демонстрация» будет показана рядом с видео.
-->
media: [Короткая демонстрация](https://github.com/user-attachments/assets/00000000-0000-0000-0000-000000000000)
:end-cl:
```

### Порядок и привязка к изменениям

Изображения, видео и внешние ссылки не сортируются по типу. Они появляются слева направо и сверху вниз ровно в порядке строк `media:`. Когда начинается следующая запись изменения, последующие строки `media:` относятся уже к ней.

```md
:cl: Имя автора
- add: Добавлен новый автомат с напитками.
<!-- Первым у этой строки появится изображение. -->
media: ![Автомат в техническом тоннеле](https://example.org/changelog/vendor.png)
<!-- Вторым — видео, без переноса в отдельную «секцию видео». -->
media: [Работа автомата](https://example.org/changelog/vendor.mp4)
<!-- Третьей — ещё одна фотография. -->
media: ![Меню автомата](https://example.org/changelog/vendor-menu.webp)

- fix: Исправлена выдача пустых стаканов.
<!--
Это медиа относится только к исправлению выше.
В Discord оно будет отделено от медиа предыдущей строки видимым разделителем.
-->
media: [Проверка выдачи стакана](https://example.org/changelog/cup-test.webm)
:end-cl:
```

Многострочный текст остаётся одной записью. Все расположенные после него строки `media:` прикрепляются ко всей этой записи:

```md
:cl: Имя автора
- tweak: Изменено приготовление кофе.
  Время приготовления уменьшено до пяти секунд.
  При нехватке воды теперь появляется понятное уведомление.
<!-- Изображение относится ко всем трём строкам записи tweak. -->
media: ![Новое уведомление](https://example.org/changelog/coffee-warning.png)
:end-cl:
```

> [!WARNING]
> Не начинайте новую смысловую запись обычной строкой без `add:`, `fix:`, `tweak:` или `remove:`. Такая строка будет продолжением предыдущего изменения, и медиа также останется привязано к нему.

### Прямые файлы и внешние сервисы

Прямые файлы загружаются и помещаются в галерею Discord. Поддерживаются:

- изображения JPEG, PNG, GIF и WebP;
- видео MP4, WebM и MOV;
- HTTPS-ссылки с перенаправлением на поддерживаемый файл, включая `github.com/user-attachments/assets/...`.

Страницы YouTube, Vimeo и других сервисов не являются прямыми файлами. Они сохраняют своё место среди остальных медиа, но отображаются как подписанные кликабельные ссылки:

```md
:cl: Имя автора
- add: Добавлен новый шаттл.
<!-- Прямой PNG попадёт в галерею. -->
media: ![Внешний вид шаттла](https://example.org/changelog/shuttle.png)
<!-- Страница YouTube появится следующей как ссылка «Полный обзор». -->
media: [Полный обзор](https://www.youtube.com/watch?v=dQw4w9WgXcQ)
<!-- Прямой MP4 останется третьим элементом в авторском порядке. -->
media: [Короткий полёт](https://example.org/changelog/shuttle-flight.mp4)
:end-cl:
```

### Ограничения и обработка ошибок

| Ограничение | Значение | Что произойдёт |
| --- | ---: | --- |
| Медиа в одном чейнджлоге | 20 файлов или ссылок | Всё после двадцатого элемента будет пропущено с предупреждением. |
| Медиа в одном запросе Discord | 10 элементов | Большой набор автоматически разделится на несколько последовательных сообщений. |
| Размер одного прямого файла | 10 МиБ | Вместо загрузки обработчик попытается оставить внешнюю ссылку. |
| Общий размер вложений одного запроса | 24 МиБ | Медиа автоматически разделится на несколько запросов с сохранением порядка. |
| Перенаправления при скачивании | 3 | После превышения предела останется внешняя ссылка. |

Разрешены только публичные HTTPS-ссылки через стандартный порт `443`. Адреса с логином и паролем, локальные и внутренние IP-адреса блокируются. Недоступный или неподдерживаемый файл не отменяет публикацию остальных изменений: обработчик выдаёт предупреждение и, если ссылка безопасна, показывает её как внешнюю. Небезопасная ссылка пропускается полностью.

> [!NOTE]
> Несколько новых записей обрабатываются последовательно в одном запуске. Отдельные запуски публикации также ожидают друг друга и не отменяются. Медленный файл задержит следующие элементы в текущей очереди, но обычная ошибка отдельного файла не остановит их; остановить весь запуск может только общий тайм-аут публикации.

## Как читается блок

> Сейчас настроен только стандартный чейнджлог `Main`. Дополнительные категории вроде `ADMIN:`, `MAPS:` и `RULES:` не подключены, поэтому использовать их в PR не следует: отдельный чейнджлог для них создан не будет.

- `:cl: Автор` начинает обычный чейнджлог из PR. Допустим также значок `🆑` вместо `:cl:`.
- Сразу после заголовка должна идти первая запись или HTML-комментарий: не оставляйте между ними пустую строку.
- `add`, `fix`, `tweak` и `remove` превращаются соответственно в добавление, исправление, изменение и удаление.
- `bug` и `bugfix` поддерживаются как синонимы `fix`.
- Строка без нового типа продолжает предыдущую запись. Так можно делать любое количество переносов через Enter.
- `media:` прикрепляет медиа к ближайшей предыдущей записи. Его можно повторять, смешивая изображения, GIF и видео в нужном автору порядке.
- `:end-cl:` явно завершает блок. Если маркер случайно удалён, две пустые строки подряд также считаются окончанием. Для совместимости блок без обеих границ читается до конца описания PR.
- HTML-комментарии удаляются до разбора и не считаются пустыми строками для границы блока. Подсказку к многострочной записи ставьте перед ней: комментарий между двумя строками завершит продолжение текста.

Медиа разных записей в Discord разделяется чертой. Прямые файлы попадают в галерею, а страницы внешних сервисов отображаются как ссылки. Ограничения: до 20 медиа на один чейнджлог, до 10 элементов в одном сообщении, до 10 МиБ на прямой файл и до 24 МиБ вложений в одном запросе. Лишние или недоступные файлы не останавливают остальные записи: обработчик предупреждает о проблеме и продолжает публикацию.

## Короткий вариант

Если медиа и переносы не нужны, достаточно такого блока:

```md
:cl: Имя автора
- add: Добавлена новая возможность.
- fix: Исправлена конкретная ошибка.
:end-cl:
```

Для ручного запуска GitHub Actions используется тот же формат, но с обязательным автором после `:ci:`:

```md
:ci: Имя автора
- tweak: Изменён существующий предмет.
media: ![Предмет после изменения](https://example.org/item.png)
:end-cl:
```
