# Прогресс дополнительного контента при подключении

## Назначение

Сервер RobustToolbox перед входом игрока передаёт runtime-ресурсы и ждёт подтверждения их получения. Sunrise показывает этот этап на экране подключения, не вмешиваясь в передачу файлов, ACK и последующую загрузку прототипов.

Функция охватывает все runtime-ресурсы `netres`, а не отдельные типы файлов. Данные остаются в памяти клиента, поэтому в пользовательском интерфейсе используется термин «загрузка».

## Сетевой контракт

`MsgUploadedContentManifest` передаёт упорядоченный полный снимок каталога:

- относительный `ResPath`;
- размер файла в байтах как `int`.

Сервер отправляет манифест каждому новому соединению, включая пустой, и повторяет полный снимок после каждой runtime-загрузки. Повторный путь заменяет размер без изменения порядка первого появления. Общий объём рассчитывается как `long`.

Манифест не содержит файлов, сведений об администраторе или данных БД. Сами ресурсы продолжает передавать `Robust.Server.Upload.NetworkResourceManager`.

## Расчёт на клиенте

Клиент подтверждает завершение целых файлов через `Robust.Client.Upload.NetworkResourceManager.FileExists` с интервалом проверки 100 мс.

- Нижний индикатор показывает подтверждённое отношение завершённого объёма к общему. Для набора только из пустых файлов используется отношение количества файлов.
- Верхний индикатор до первого замера анимируется, затем показывает приблизительный прогресс текущего по порядку файла.
- Скорость рассчитывается только по новым завершённым файлам и сглаживается EWMA с коэффициентом `0.35`.
- Приблизительный прогресс ограничен 95% до подтверждения файла; приблизительные значения в UI отмечаются `~`.
- Файлы, уже присутствующие при получении манифеста, учитываются как завершённые, но не участвуют в расчёте скорости.

Имя текущего файла не показывается: публичный API движка не раскрывает фактический порядок чтения.

## Инварианты и выпуск

- `RobustToolbox`, протокол передачи и жизненный цикл runtime-ресурсов не изменяются.
- Клиент не вызывает `ClearResources`, поэтому повторное подключение использует уже загруженные в память файлы.
- БД, Web API, CVar, launcher-контракты и env не изменяются.
- Клиент и сервер необходимо выпускать одним билдом контента, поскольку добавлен новый `NetMessage`.
- Перед общим выпуском сценарий проверяется на сервере с репрезентативным объёмом runtime-ресурсов при `transfer.http=false` и `transfer.http=true`.
